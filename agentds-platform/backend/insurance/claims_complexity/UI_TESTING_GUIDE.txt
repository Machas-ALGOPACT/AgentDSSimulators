UI TESTING GUIDE
================================================================================

This guide covers everything needed to test and integrate the claims complexity
model with a user interface.

OVERVIEW
--------

The model predicts claim complexity (Simple, Moderate, Complex) based on:
  - Required inputs: ClaimID, PolicyID, ClaimDate, ClaimType, ReportedDamage, NumParties, Description
  - Optional inputs: HolderAge, VehicleType, AnnualMileage, LocationUrban, CreditScore, PolicyStart, PolicyEnd

OUTPUT
------

  prediction: "Simple" | "Moderate" | "Complex"
  confidence: 0.85 (85% certainty)
  probabilities: {"Simple": 0.15, "Moderate": 0.41, "Complex": 0.44}

TESTING
-------

Run: python single_input_test.py

This script:
  - Shows 4 realistic test cases
  - Displays field documentation
  - Shows actual model predictions
  - Provides UI form template

KEY POINTS
----------

1. Description field is critical (minimum 50 characters)
   - Model uses NLP to analyze claim descriptions
   - Quality descriptions improve accuracy

2. Optional fields are auto-imputed if missing
   - System fills with median/mode values
   - Don't force users to enter policy details

3. Prediction time < 100ms (suitable for real-time UI)

4. Model accuracy 96% on validation data

5. Confidence ~40% is normal (model sees 3 classes as balanced)

VALIDATION RULES
----------------

ClaimID: Required, non-empty text
PolicyID: Required, non-empty text
ClaimDate: Valid datetime (YYYY-MM-DD HH:MM)
ClaimType: Must be from: Collision/Comprehensive, Liability/Bodily Injury, 
           Theft/Comprehensive, Fender-Bender, Vandalism, Other
ReportedDamage: Positive number >= 0
NumParties: Positive integer >= 1
Description: Minimum 50 characters

Optional field validation:
HolderAge: 16-120 if provided
CreditScore: 0-1 range if provided
LocationUrban: 0 or 1 only
